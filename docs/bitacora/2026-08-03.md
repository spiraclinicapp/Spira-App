## 4. Lo no-obvio

- **El texto fantasma más claro SIEMPRE salta.** Bajar la opacidad no integra: mientras la sugerencia sea de otro tono/claridad que lo tipeado, el ojo la lee aparte (peor si parte una palabra al medio: "alve"+"tide"). La integración se logra con **misma tinta + resalte** (foreground igual, la señal va al fondo), no tocando la opacidad del texto.
- **Overlay de autocompletado inline: dibujar lo tipeado y el fantasma en UNA sola tirada.** Si el `<input>` pinta su texto y un `<div>` aparte pinta el fantasma, las métricas difieren y se desalinean. Solución: input con `color:transparent` (solo deja el cursor) + un overlay que pinta value+ghost juntos, mismo box/tipografía (`…fieldInput` + `box-sizing:border-box` global). El cursor cae justo en el borde del resalte.
- **`e.stopPropagation()` en un handler de React SÍ frena los listeners de `document`** (el Escape del `Modal`): React 18 despacha en el root container, descendiente de `document`, así que detener la propagación ahí evita que el evento llegue a los listeners de `document`. Sin eso, Escape cerraba el desplegable **y** el modal en la misma tecla.
- **`AutocompleteInput` dentro de `FormField` (que es un `<label>`) es seguro:** las opciones del desplegable son `<button>` (contenido interactivo), y el spec HTML dice que el `<label>` no reenvía el click a su control cuando el target es interactivo → no hay reapertura ni doble-foco. No hubo que tocar `FormField`.
- **Enter con el fantasma a la vista debe aceptarlo.** Si Enter submitea lo tipeado ("Alve") con la sugerencia "Alvetide 184/22 mcg" a la vista, crea un alta con el **nombre a medias** — justo el duplicado que la feature evita. Enter ahora acepta el fantasma (como Tab/→); para crear a propósito un prefijo de un nombre existente quedan Escape o el botón.
- **`textSuggestions` debe deduplicar:** en el modo texto simple `value` es el string crudo y es la `key` de la lista → sin dedupe, key repetida (lo había marcado el review del Paso 1).
- **No se puede screenshotear el preview** (login + documento oculto) **ni** archivos fuera del proyecto (se abren como snapshot estático). Para la validación visual del fantasma se le mandó al Director un **mock estático fiel** (mismos tokens/estructura) por el chat; lo demás lo confirmó él logueado.
- **La red a GitHub estuvo intermitente:** el `push` colgó dos veces (2 min y 5 min) → se corrió en **segundo plano** y entró (exit 0). Los `git fetch` también colgaban.
- **El Director mergeó la PR #23 con el Paso 1, no la feature entera.** Cronología: cerré Paso 1 → PR #23 (título "Paso 1") → hice Paso 2 y lo pusheé a la MISMA rama → actualicé título/cuerpo de la #23 a "Paso 1+2". Pero el Director **ya había mergeado la #23 en `adb495b` (Paso 1)**; mis 5 commits del Paso 2 llegaron a la rama con la PR ya cerrada. **Una PR mergeada no se reabre empujando commits** ni cambiándole el título (el PATCH devolvió "9 commits" —los del Paso 1— aunque la rama ya estaba en `3bc56d6`: pista de que estaba mergeada). Lección: cuando el Director puede mergear en paralelo, **no stackees Paso N+1 sobre la rama de una PR viva** — o abrís rama nueva desde el merge, o asumís que va a hacer falta PR nueva. Detección al cierre: el `push` de la bitácora a `main` rebotó por non-fast-forward → `pull --rebase` reveló el merge `d8fd734`.
