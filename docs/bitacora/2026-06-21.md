---

## 1. Objetivo

Cerrar el bug **"Próximas visitas (7 días): 0"** del Resumen de Track. Causa raíz (de datos, no de
query): no existía UI para definir el **cronograma** de un protocolo, así que randomizar no generaba
visitas programadas. La feature permite **definir el cronograma dentro de la app** y
**generar/actualizar** las visitas programadas de los pacientes randomizados a partir de él.

Spec: `docs/superpowers/specs/2026-06-20-cronograma-protocolo-design.md` ·
Plan: `docs/superpowers/plans/2026-06-20-cronograma-protocolo.md`.

## 2. Qué entra

### 2.1 Migraciones
- **0026 — RLS + RPCs del cronograma** (ya estaba al iniciar la jornada; **aplicada en prod ✅**).
  Endurece la RLS de `visit_definitions` (edición gerencia/track-admin, cierra el borrado directo) +
  RPCs `sync_protocol_schedule(p_protocol_id, p_apply)` (preview/aplicar, no toca atendidas) y
  `delete_visit_definition(p_def_id)` (bloquea si hay atendidas).
- **0027 — `count_deletable_visits`** (SECURITY DEFINER): impacto del borrado `{deletable, attended}`
  con la **misma authz que el borrado**, no bajo la RLS de lectura del caller. **Pendiente de aplicar.**
- **0028 — `protocols` SELECT += `has_min_role('track','admin')`**: un track-admin antes no veía
  ningún protocolo (la policy exigía rol `leader` exacto) y no llegaba a la pestaña que sí puede
  gestionar. Aditivo. **Pendiente de aplicar.**

## 3. Estado

- `npm run typecheck` + `npm run build` **verdes** en cada paso.
- **Verificación adversarial multi-agente (2 rondas, ~34 agentes).** Todos los hallazgos confirmados,
  corregidos:
  - 🔴 **El crítico**: el conteo de impacto del borrado se leía por `v_track_visits` (security_invoker)
    bajo la RLS del caller, pero `patient_visits` solo lo ven gerencia/coordinadora asignada. Como el
    borrado es SECURITY DEFINER, un track-admin no asignado veía "0 a borrar" y el borrado **sí**
    eliminaba N visitas reales. → conteo movido a la RPC `count_deletable_visits` (0027).
  - El confirm muestra el impacto real y **deshabilita "Quitar"** si hay atendidas (preempta el bloqueo).
  - Pulidos: `deleteDefinition` traduce `23503` (carrera); `move()` hace `refetch` también en error
    (reorder no atómico); race del fetch de impacto anclado por contador de request; copy del confirm
    coherente; indicador "Guardando orden…".
- **Migraciones:** 0026 ✅ aplicada · **0027 ⏳ pendiente** · **0028 ⏳ pendiente**.
