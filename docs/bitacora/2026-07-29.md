## 3. Fix del parpadeo del ícono del login (PR #21)

**Causa raíz:** el ícono del sobre es un `<span>` absoluto que va **antes** del input en el DOM y **sin `z-index`**. La regla global de foco de Spira levanta todo input con `transform: translateY(-1px)`, y el `transform` lo promueve a stacking context propio → su fondo blanco pasaba a pintarse **por encima** del ícono. Con la transición de foco + el repintado del fondo del autocompletado de Chrome, se veía como parpadeo.

**Fix:** el ícono pasa a una clase reusable `.spira-input-affix` con **`z-index: 1`** (siempre por encima del input) y acompaña el levante de 1px del campo en `:focus-within` (con guarda de `prefers-reduced-motion`). Bonus on-brand: se **neutraliza el fondo celeste + texto negro** que Chrome/WebKit ponen al campo autocompletado (`box-shadow: inset` + `-webkit-text-fill-color` + transición congelada), theme-aware por tokens. Archivos: `src/styles/tokens.css`, `src/shell/Login.tsx`. Verificado por el Director en su navegador.

## 4. Lo no-obvio

- **Un `transform` de foco puede tapar un ícono afijo.** El levante de 1px promueve el input a stacking context propio; si el ícono va antes en el DOM y sin `z-index`, el fondo del input lo tapa. `z-index: 1` en el afijo lo resuelve — patrón reusable para cualquier input con ícono a la izquierda.
- **El autofill de Chrome/WebKit rompe la paleta y dispara repintados.** Se neutraliza con el truco `box-shadow: inset 0 0 0 1000px <bg-token>` + `-webkit-text-fill-color`, theme-aware; de paso mata el flicker que alimentaba.
- **Compartir el panel > duplicar.** Extraer `DoctorRequest` y reusarlo en modal + popup dio consistencia gratis; el modo `bare` evita el doble título en el popup y `startExpanded` abre el picker de una.
- **El preview corre logueado o no se puede QA-ear.** La verificación del popup necesita sesión autenticada; el agente **no puede loguearse** (ingresar contraseñas está fuera de límites, creds fuera del chat). Quedó diferida al Director (checklist en la PR).
- **El "Repository not found" era el usuario de git mal seleccionado**, no un bloqueo de auth. Con el usuario correcto, `push` + PRs vía API REST (`git credential fill` + Node) andan.
- **El repo auto-abre una PR bare al pushear una rama** (PR #20 y #21 aparecieron con título default + cuerpo vacío tras el push). Se les carga título/cuerpo por API REST (a la #20 antes del merge; la #21 se mergeó con el título default).
- **Graphify descartado:** un grafo es una foto que queda stale, no reemplaza leer el código y cargarlo cuesta **más** tokens; docs + memoria cumplen mejor. ⚠️ sube docs no-código a LLMs externos (gobernanza clínica).
