## 3. Trabajo realizado — Paso 2: portar Track → Pacientes

Se planificó (plan mode, con revisión de un agente de diseño) y se ejecutó. Decisiones de stack: sin
dependencias nuevas (ni react-query ni react-router); tipos a mano (no hay tipos generados de Supabase).

### 3.1 Router de contenido reutilizable
Hasta hoy el `AppShell` renderizaba el mismo placeholder para todos los submódulos. Se introdujo una
capa de despacho:
- `src/views/types.ts` — contrato `ViewProps { module, submodule }` / `ViewComponent`.
- `src/views/registry.tsx` — `resolveView(moduleKey, subKey)` con **fallback a `Placeholder`** para lo
  no portado.
- `src/views/Placeholder.tsx` — el placeholder anterior extraído como vista (idéntico).
- `AppShell.tsx` — el bloque de contenido ahora hace `resolveView(...)`; el shell mantiene el marco
  scroll+padding como único dueño.

### 3.2 Niveles de rol en el front
- `src/lib/auth.tsx` — se agregó `ModuleRole`, `roleRank` (espejo de `role_rank` SQL de la migración
  0009) y `hasMinRole(module, min)`; el query pasó a `select('module, role')`. `modules` quedó intacto
  (no rompe a sus consumidores).

### 3.3 Capa de datos
- `src/lib/useSupabaseQuery.ts` — hook genérico `{ data, loading, error, refetch }` con cleanup
  (flag `active`, igual que `AuthProvider`). Es la convención de fetch para todas las vistas.
- `src/data/patients.ts` — `PatientRow` (tipos a mano) + `usePatients()` con embedding PostgREST
  `patients → enrollments → protocols`. La RLS scopea sola (coordinadora ve solo sus protocolos;
  pharma/gerencia ven todos).

### 3.4 La vista
- `src/views/track/PatientsView.tsx` — lista (solo lectura): toolbar con búsqueda local, tabla
  (código en mono tabular, nombre, badge de estado `activo`/`inactivo`, chips de protocolo en teal de
  Track), y estados loading/vacío/error siguiendo el patrón visual de `Login`.
- `AppShell.tsx` — el botón "Nuevo paciente" se gatea por `hasMinRole('track','operator')` (en v1 es
  no-op; el alta es la próxima rebanada).
- `src/components/Icon.tsx` — se sumaron los íconos `x` y `alertCircle`.

## 4. Revisión de código y accesibilidad

Se corrió una revisión adversarial (2 finders en paralelo: correctitud + limpieza/a11y).
- **Correctitud:** sin bugs introducidos. Verificado: embedding to-one vs array de PostgREST, closures
  de `hasMinRole`, ciclo loading/error/refetch/unmount del hook, doble-fetch de StrictMode, `noUnusedLocals`.
- **Accesibilidad — aplicado:** (1) foco visible global (`:focus-visible` en `tokens.css`) + se sacaron
  los `outline:none` que lo tapaban; (2) roles ARIA (`table`/`row`/`columnheader`/`cell`) en la tabla;
  (3) el texto del chip de protocolo usa `accentSolid` (contraste, clave para el futuro Pharma).
- **Anotado para después:** unificar `StateCard`/`Placeholder` en un `EmptyState`; mover `action` +
  `minRole` a la definición de `SubModule` (hoy el gateo del botón es un special-case de `track/pacientes`);
  unificar el tinte `accent + '14'` a `color-mix`.
- **Flag (preexistente, no de este cambio):** `gerencia` está en `ModuleKey` pero no en `MODULES` →
  un usuario solo-gerencia vería todo bloqueado pese al acceso por RLS. Lo resuelve el panel de gerencia.
